PROJECT 3: PACKET TRACER – USE PING AND TRACEROUTE TO TEST NETWORK CONNECTIVITY

Introduction

This project was carried out using Cisco Packet Tracer to test and restore network connectivity. The network contained three routers, four switches and four PCs. Both IPv4 and IPv6 connectivity were tested using ping and traceroute.

The main aim was to identify where communication was failing, correct the configuration problems and confirm that the PCs could communicate successfully across the network.

Part 1: Testing and Restoring IPv4 Connectivity

The first IPv4 test was carried out from PC1 to PC3 using:

ping 10.10.1.18

The first test failed with a destination host unreachable message. I checked the routers to find where the problem was coming from.

R1 did not have a route to the PC3 network, so a static route was added:

ip route 10.10.1.16 255.255.255.240 10.10.1.5

R2 also did not have a route to the PC3 network. The following route was added:

ip route 10.10.1.16 255.255.255.240 10.10.1.10

R3 also needed a return route to the PC1 network:

ip route 10.10.1.96 255.255.255.224 10.10.1.9

The IPv4 settings on PC3 were also checked and configured as follows:

- IP Address: 10.10.1.18
- Subnet Mask: 255.255.255.240
- Default Gateway: `10.10.1.17

After making the corrections, PC1 was able to communicate with PC3 successfully.

Final IPv4 Ping Result

The final ping from PC1 to PC3 showed:

- Packets sent: 4
- Packets received: 4
- Packet loss: 0%
- Average time: 12 ms

This confirmed that IPv4 connectivity was restored.

IPv4 Traceroute

The traceroute from PC1 to PC3 showed the following path:

10.10.1.97 → 10.10.1.5 → 10.10.1.10 → 10.10.1.18

The trace completed successfully in four hops.

Part 2: Testing and Restoring IPv6 Connectivity

IPv6 connectivity was tested between PC2 and PC4.

The main problems found during the IPv6 configuration involved routing and default gateways. The required IPv6 routes were configured on the routers and the correct link-local default gateways were set on the PCs.

PC2 used:

2001:DB8:1:1::2

PC4 used:

2001:DB8:1:4::2

After correcting the configurations, PC2 was able to communicate with PC4 successfully.

Final IPv6 Ping Result

The final IPv6 ping from PC2 to PC4 was successful with:

- Packets sent: 4
- Packets received: 4
- Packet loss: 0%

This confirmed that IPv6 connectivity was restored.

 IPv6 Traceroute

The IPv6 traceroute showed:

2001:DB8:1:1::1 → 2001:DB8:1:2::1 → 2001:DB8:1:3::2 → 2001:DB8:1:4::2

The trace completed successfully in four hops.

Conclusion

This project helped me understand how ping and traceroute can be used to test network connectivity and locate connection problems. I also learned how incorrect or missing routes and default gateway settings can prevent communication between different networks.

After making the required corrections, both IPv4 and IPv6 connectivity were successfully restored. The final ping tests showed 0% packet loss, while the traceroute tests successfully reached their destinations in four hops.
